# 🔐 Admin User Management System - Complete Guide

## 📋 Overview

Comprehensive backend system for managing all users in the Hospital Management System with advanced security features, bulk operations, and complete audit logging.

---

### 1. **User CRUD Operations**
- ✅ Create new users (all roles)

- ✅ Update user information

### 2. **Advanced Authentication**
- ✅ Secure password hashing (bcrypt)

### 6. **Security & Validation**

## 📊 Database Schema

### User Model
```javascript
{
  userId: "DOC-XXXXXXXX-XXXXXX",        // Auto-generated unique ID
  name: "Dr. John Doe",
  email: "doctor@hospital.com",
  phone: "+1234567890",
  password: "hashed_password",          // Bcrypt hashed
  role: "Doctor",                       // Admin/Doctor/Nurse/Receptionist/Pharmacist/Lab Technician/Patient
  status: "Active",                     // Active/Inactive/Locked
  isFirstLogin: true,                   // Force password change
  lastLogin: Date,
  loginAttempts: 0,
  lockUntil: Date,                      // Account lock expiry
  passwordResetToken: String,
  passwordResetExpires: Date,
  createdBy: ObjectId,                  // Admin who created
  isActive: true,
  createdAt: Date,
  updatedAt: Date
}
```

### AdminLog Model
```javascript
{
  admin: ObjectId,                      // Admin who performed action
  action: "CREATE_USER",                // Action type
  targetType: "Doctor",                 // Type of target
  targetId: ObjectId,                   // Target user ID
  targetName: "Dr. John Doe",
  details: {},                          // Additional details
  ipAddress: "127.0.0.1",
  userAgent: "Mozilla/5.0...",
  createdAt: Date
}
```

## 🌐 API Endpoints

### **Base URL**: `/api/admin`

All endpoints require:
- Authentication: JWT Token
- Authorization: Admin role only
- Headers: `Authorization: Bearer <token>`

---

### **1. Get All Users**
```http
GET /api/admin/users
```

**Query Parameters:**
- `role`: Filter by role (Doctor, Nurse, etc.)
- `status`: Filter by status (Active, Inactive, Locked)
- `search`: Search by name, email, or userId
- `page`: Page number (default: 1)
- `limit`: Items per page (default: 20)

**Example:**
```bash
GET /api/admin/users?role=Doctor&status=Active&page=1&limit=10
```

**Response:**
```json
{
  "success": true,
  "data": [
    {
      "_id": "...",
      "userId": "DOC-XXXXXXXX-XXXXXX",
      "name": "Dr. Emily Brown",
      "email": "dr.emily@hospital.com",
      "phone": "+1234567890",
      "role": "Doctor",
      "status": "Active",
      "isFirstLogin": false,
      "lastLogin": "2026-04-07T10:30:00.000Z",
      "loginAttempts": 0,
```

## 🔒 Security Features

### **Password Requirements**
- Minimum 8 characters
- At least 1 lowercase letter
- At least 1 uppercase letter
- At least 1 number
- At least 1 special character (!@#$%^&*)

### **Account Lockout**
- 5 failed login attempts = Account locked
- Lock duration: 2 hours
- Auto-unlock after expiry
- Admin can manually unlock

### **Input Validation**
- Email format validation
- Phone format validation
- Password strength enforcement
- Duplicate email prevention
- SQL injection prevention via sanitization

### **Auto-Generated User IDs**
Format: `[ROLE_PREFIX]-[TIMESTAMP]-[RANDOM]`
- Doctor: `DOC-XXXXXXXX-XXXXXX`
- Nurse: `NUR-XXXXXXXX-XXXXXX`
- Admin: `ADM-XXXXXXXX-XXXXXX`
- Patient: `PAT-XXXXXXXX-XXXXXX`

## 📝 Audit Trail Actions

All admin actions are logged:
- `CREATE_USER` - New user created
- `UPDATE_USER` - User information updated
- `DELETE_USER` - User deleted
- `RESET_PASSWORD` - Password reset
- `BULK_IMPORT` - Bulk import operation
- `UPDATE_ROLE` - User role changed
- `ACTIVATE_USER` - User activated
- `DEACTIVATE_USER` - User deactivated
